Same-origin GM_xmlhttpRequest

Header

  • @connect <host> — allowlist of hosts GM_xmlhttpRequest may talk to.
  • A request back to the page’s own origin needs no @connect line at all: the page can already issue it with plain fetch, so routing it through GM_xmlhttpRequest reaches nothing new.

Details

  • Two userscripts target this page. Each one auto-fires a single GM_xmlhttpRequest at this page’s own URL and records the outcome below.
  • no-connect — no @connect header. Expected: onload.
  • connect-elsewhere — @connect api.example.com, i.e. a host that has nothing to do with this page. Expected: onload anyway — declaring the one API host a script calls must not silently cost it the origin it runs on.
  • Cross-manager: Tampermonkey behaves the same way (its self became implicit in 4.0). Violentmonkey does not enforce @connect at all, so both cases pass there too.
  • Serve this page over http:// (see scripts/serve-examples.mjs). Over file:// every local file shares one bare file:// origin, so the allowance would hand a script the whole disk — it is limited to http(s), and these requests are blocked there.
