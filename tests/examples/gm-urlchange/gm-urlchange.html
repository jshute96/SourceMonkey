Userscript examples for window.onurlchange

API

  • @grant window.onurlchange — adds a synthetic urlchange event to the script’s window. Feature-detect with if (window.onurlchange === null); without the grant the property is undefined.
  • window.addEventListener('urlchange', info => …) — the handler receives an object whose url is the document’s new URL.
  • window.onurlchange = fn — the handler-slot form. It takes its place in registration order alongside the addEventListener handlers, so assigning it first means it fires first.

Details

  • The buttons below are wired by this page’s own script, not by the userscript — so every navigation is a genuine page-initiated one, the case a userscript actually has to observe.
  • Nothing fires on the initial document load. A script handles the URL it started on itself, then listens for changes.
  • There is no de-duplication: a replaceState to the URL you are already on still fires, because the event tracks history updates, not distinct URLs.
  • Full page reloads are not urlchange events either — the script simply runs again in the new document.
  • The handler is called with a bare { url } object, not a DOM Event.
