Userscript examples for DOM injection

APIs

  • GM_addStyle(css) — inject a <style> with the given CSS text into document.head. Returns the inserted <style> element so the userscript can remove or modify it later.
  • GM_addElement(tagName, attrs?) — create an element of tagName, copy attrs onto it (including a textContent key as inner text), and append it to the default parent. <head> for script / style / link / meta / title / base, <body> for everything else (matches VM; TM diverges — see Details below).
  • GM_addElement(parent, tagName, attrs?) — same, but appended to the given parent element instead of the default.

Details

  • USER_SCRIPT-world injection is exempt from page CSP, so these calls succeed even on pages that block inline scripts/styles.
  • The parent-form button appends a <span> directly into the playground div below.
  • The default → body button appends a <p>: p isn’t a head tag, so the runtime sends it to <body>.
  • Cross-manager difference (default parent): SourceMonkey and Violentmonkey route the no-parent form by tag — head-tags (script, style, link, meta, title, base) go to <head>, everything else goes to <body>. Tampermonkey appends to <head> regardless of tag, so under TM the <p> from the button above lands in <head> instead.
  • The default → head button appends a <title>: that is a head tag, so it goes to <head>. Each click appends another copy — inspect <head> in DevTools to see them stack up. The browser tab text doesn’t change because document.title comes from the first <title> in tree order, not the last.
  • The log records each call’s actual parent so you can verify where it landed without inspecting the DOM by hand.
  • Reset removes every element this userscript has injected so far (no matter which parent it went to) and restores the playground’s original contents.
