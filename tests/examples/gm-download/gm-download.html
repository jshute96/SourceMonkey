Userscript examples for GM_download

APIs

  • GM_download(details) or GM_download(url, name) — save a file to the browser’s download directory. Returns a control object with an abort() function. Optional onload, onerror, onprogress, and ontimeout callbacks report on the transfer.

Details

  • Each preset button runs a canned call and fills the form with the arguments it used, so the next call can be a small edit of one that worked. Hover a preset to see the exact call it makes.
  • Every call saves into your normal downloads folder — a small text file next to this page, an absolute cross-origin https:// URL, a data: URL, and a blob: URL built in the page.
  • Some presets are deliberate failures, and they fail at different stages:
    • 404 — passes every check and fails in the transfer, so this is the one that exercises the download manager’s own error reporting.
    • file:// URL — refused up front; a userscript shouldn’t be able to pull local files onto disk.
    • ../ name — refused up front for trying to escape the download directory.
    Managers differ in the error value they report; the log shows whatever yours says.
  • An empty form field means the argument is omitted, not passed as an empty value — managers treat those differently. Use "" in a JSON field to send an actual empty string.
  • The form doesn’t check arguments before calling. Submitting with no url makes the call anyway, so the log shows how GM_download itself refuses it.
  • In SourceMonkey, a failed download shows up on the script’s Log tab at warning level, so there’s somewhere to look when nothing arrives. Successful downloads aren’t logged.
  • onprogress ticks appear in the log while a transfer runs. SourceMonkey polls the download manager (~500 ms) and only does so when the script supplies an onprogress, so a transfer that finishes inside the first poll logs none — expect ticks only on a slow link or a large file. A server that sends no Content-Length yields ticks with no total.
  • abort() acts on the most recent call, and only reaches transfers the manager actually controls. The blob:/data: path is handed straight to the browser, so aborting it after the fact does nothing.
  • Opening this page from disk (a file:// URL) makes the relative filename preset resolve to file:// too, which SourceMonkey refuses for the same reason as the file:// preset — serve the page over http(s) to see it succeed. Every other preset uses an absolute URL, so they behave the same either way.
