Userscript examples for GM_download

APIs

  • GM_download(details) or GM_download(url, name) — save a file to the browser’s download directory. Returns a control object with an abort() function. Optional onload, onerror, onprogress, and ontimeout callbacks report on the transfer.

Details

  • Each button downloads something into your normal downloads folder — a small text file next to this page, a data: URL, and a blob: URL built in the page.
  • The last two buttons are deliberate failures: a file:// URL (refused — a userscript shouldn’t be able to pull local files onto disk) and a name that tries to escape the download directory. Managers differ in the error value they report; the log shows whatever yours says.
  • abort() only reaches transfers the manager actually controls. The blob:/data: path is handed straight to the browser, so aborting it after the fact does nothing.
  • Opening this page from disk (a file:// URL) makes the buttons that fetch sample.txt resolve to file:// too, which SourceMonkey refuses for the same reason as the deliberate-failure button. Serve the page over http(s) to see those succeed; the data: and blob: buttons work either way.
