Userscript examples for GM_registerMenuCommand

APIs

  • GM_registerMenuCommand(name, callback, accessKeyOrOpts?) — register an entry the userscript manager exposes in its UI for this page. Returns an id usable with GM_unregisterMenuCommand. Pass {id: 'stable-id'} as the third arg to update an existing entry in place.
  • GM_unregisterMenuCommand(id) — remove the entry previously returned by GM_registerMenuCommand. Unknown ids are silently ignored.

Details

  • Each userscript manager renders these entries in its own UI: SourceMonkey, Tampermonkey and Violentmonkey all list them under their script in their toolbar popups.
  • Entries are scoped to the active tab. Navigating to a different document clears them; the new document’s userscript re-registers from scratch.

By name (each Register gets a new id)

Without options.id, GM_registerMenuCommand mints a fresh id every call, so clicking Register twice gives two registrations with the same caption. The list below shows both; the manager’s menu shows the caption once. Unregister removes the most-recently-added one (LIFO).

  • Tampermonkey and SourceMonkey: picking the menu entry runs every registration, and it stays in the menu until the last one is unregistered.
  • Violentmonkey keys commands by caption, so a repeat replaces the entry, and the first Unregister removes it.

By fixed id (re-register updates in place)

With options.id = 'bar-settings', the second and later Register calls update the existing entry in place — the menu only ever shows one row for that id. Unregister removes that one row; clicking it again is a silent no-op.
