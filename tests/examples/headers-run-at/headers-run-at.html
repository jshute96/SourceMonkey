Userscript examples for @run-at

Header

  • @run-at document-start — runs before the DOM has parsed. document.readyState is loading and document.body may be null.
  • @run-at document-end — runs after DOMContentLoaded, before subresources finish. readyState is interactive.
  • @run-at document-idle — default. Runs after load. readyState is complete.

Details

  • Three userscripts match this page, one per @run-at value. Each appends one row to the log with the readyState it observed.
  • You should see one row per variant. Injection order follows the @run-at ordering (document-start → document-end → document-idle), since Chrome treats @run-at as an “earliest” bound.
  • The readyState values aren’t tied 1:1 to the @run-at value in practice — on small local pages, Chrome’s chrome.userScripts injection often arrives after the document has already reached interactive, so document-start and document-end can both observe readyState=interactive. document-idle still cleanly observes complete because it waits for load.
  • The page itself logs lifecycle markers into window.__SM_PAGE_TIMING__ so you can correlate timing from DevTools.
