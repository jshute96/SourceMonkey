Userscript examples for @connect denial

Header

  • @connect <host> — allowlist of hosts GM_xmlhttpRequest may talk to. Strict by default: a script with no @connect lines is blocked from every cross-origin URL.
  • @connect * — wildcard. Allow all hosts.

Details

  • Three userscripts target this page. Each one auto-fires a single GM_xmlhttpRequest at http://127.0.0.1:1/ when it runs and records the outcome below. Port 1 is a closed loopback port — connections refuse fast, so the test is reliable offline.
  • no-connect — no @connect. Expected: blocked by this script’s @connect rules.
  • connect-mismatch — @connect somewhere.else.example.org. Host doesn’t cover 127.0.0.1. Expected: blocked by this script’s @connect rules.
  • connect-allowed — @connect 127.0.0.1. Policy allows the request through; the network call itself fails with connection-refused because nothing is listening on port 1. Expected: an onerror without the policy-block substring.
  • The denial happens in the service worker before any fetch is issued, so a blocked request never leaves the browser.
  • Every denial also lands in the script’s Log tab, naming the host and the @connect line that would allow it.
  • Requests to the page’s own origin are the exception: they need no @connect at all. See the same-origin example.
