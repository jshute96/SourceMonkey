Userscript examples for @require scope

Header

  • @require <absolute URL> — page-world and content-world pull lib.js in by its raw.githubusercontent.com URL. Absolute URLs are the only form TM/VM/GM accept, so those two scripts are portable to any manager.
  • @require ./relative-lib.js — relative-require uses a relative path instead, resolved against the script’s own URL. That is a SourceMonkey extension, so this script runs only here.
  • @inject-into page vs @inject-into content — the portable pair run in different worlds, using the same library.

Details

  • lib.js declares a class, a const and a function at its top level. Requires are concatenated ahead of the script body into one injected entry, so all three are in scope for the body — the same thing Tampermonkey and Violentmonkey get by concatenating into a single IIFE.
  • The class and const are the interesting ones. They are script-scoped, so under an arrangement that gave each @require its own injected script they would be invisible to the body no matter what. function and var would leak through globalThis either way.
  • Scope is per script, not per world: the MAIN-world script and the isolated-world script each get their own copy of the library in their own wrap function.
  • Two of the three scripts are portable, one is not, and the status line is how you tell them apart. SourceMonkey resolves both @require spellings and reaches 3 of 3; a manager that only understands absolute URLs runs the portable pair and stops at 2 of 3.
  • relative-require requires both libraries — ./lib.js for the shared helper and ./relative-lib.js for its own bindings. So it also pins that requires are concatenated in header order and land in one scope with each other and the body.
  • The status line counts the rows the scripts append. Each runs in its own world and they can’t share a counter, so the shared DOM is what they agree on — and 0 of 3 stays on the page if the manager injected none.
  • The library must not reach the page. Even in the MAIN world, its top-level bindings are locals of the wrap function, so window.REQUIRE_SCOPE_CONST stays undefined. Each script reports this as leakedToWindow.
