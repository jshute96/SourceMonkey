Userscript examples for @inject-into

Header

  • @inject-into page — run in the page’s own MAIN world. The script shares window with the page; it can read page globals and the page can read what it sets. No GM_* bindings are available.
  • @inject-into content — run in an isolated USER_SCRIPT world. The DOM is shared with the page, but window is a separate JS realm. Page globals are not visible. GM_* bindings are available when granted.

Details

  • The page sets window.__SM_PAGE_MARKER__ in an inline <script>. Each userscript tries to read it and reports what it saw.
  • The MAIN-world script (page.user.js) should read it as 'i-am-the-page-world'. The USER_SCRIPT-world script (content.user.js) should read it as undefined.
  • Both scripts share the same DOM, so both can write to #log — world isolation is only about JS heap visibility, not DOM access.
